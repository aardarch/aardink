# Spike: inline layout (0.9, unit 3)

Status: **done (automated steps)**; S2's p95 comparison and S9 are pending a run alone on the
machine, and nothing here has run on a physical Android device. This report records what the spike
proved, per platform, before the inline UI in `docs/AARDINK_ROADMAP.md` §7.3 builds on it. Each step
lists its evidence: a test in the repository or a command's result.

**The question:** can text and rows outside the document be added per line, on demand, on all three
platforms, with every column mapping correct and the 5,000-line gates intact?

The spike is internal to `:editor` and adds nothing public: `checkAbiAll` has nothing to report for
it. The switch is `EditorView.injections`, null by default, and nothing in the library sets it.

## The model

- Injected text is spliced into the line's `AnnotatedString` as real characters, with a per-line
  `OffsetMap`. With nothing injected the map is `OffsetMap.Identity`, which answers with what it is
  given and allocates nothing.
- `LineLayout(result, map)` replaces `TextLayoutResult` as the `LineLayoutCache` value and in
  `VisibleLine`, and speaks document columns only. A column has three layout positions when text is
  injected at it, as `x|gy` shows for ghost text `g`: where a caret goes (`toLayout`), where the
  character is (`charIndex`), and where the range before it ends (`rangeEnd`).
- Added rows are hard line breaks inside the same paragraph, so `layout.lineCount` counts them and
  `VisualLineMap` is unchanged. `LineLayout` works out which rows hold no document column
  (`isInjectedRow`, `textRow`, `lastTextRow`), only when the injected text has a break.

### How the tests were checked

Passing tests prove little until they have been seen to fail, and much of this was written by an
agent that was interrupted. So each piece of logic the plan names as a known cost was broken on
purpose, one at a time, and the spike's tests run against it: 32 mutants of `LineLayout`,
`OffsetMap`, `EditorView`, the drawing, the gutter, sticky scroll, the minimap, column selection and
the pointer. All 32 are now killed, on the JVM. Four survived at first, and each was a real gap
in the tests, not in the code, now closed:

- Nothing proved `setRows` runs without soft wrap.
- The fold placeholder test clicked too close to the hint to reach a position past the line.
- Column selection was tested only on lens rows, where a stray caret merges into the line's own
  range, and not on ghost rows below a line, where it does not.
- `rowEndX` was tested with the hint at the line's end, where the mixed-up columns happen to agree.

## Found along the way

- **A text's empty last row is measured with the default font on skiko.** A lens above an empty
  line puts the line's only row last in the paragraph, and Skia measures that row without the
  row's style, so the caret came out the wrong height and place. `LineLayout.cursorRect` draws it
  from the row above, one pitch down. This is the one place where hard breaks needed a correction.
- **Row 0 can sit off the view's pitch.** `rowShift` counts from `getLineTop(0)` when a line has
  hard breaks, so added rows keep their own band. A line without breaks takes the old path.
- **`map(b) - 1` does land in injected text**, with a hint at the end of a range. `charBox` and
  `rangeEnd` are why each column has three positions, not one.
- **A minimap tile went stale when a lens moved.** Its short cut compared the document, the tokens
  and the row count, and a lens moving from one line to another changes none of them. It now
  compares `injectionVersion` too.
- **A browser test has two seconds.** The pixel sweep is about fifty renders a test, so
  it runs on the JVM, and the positions it depends on run in the browser through `InlineColumnsTest`.
  No assertion failed there; only the time ran out.

What the units after the spike still have to deal with:

- **Off-screen estimates count what is asked for, not what fits.** `estimateRows` has only the
  line's length and the `LineInjections`. A break in an injection that `fitted` later drops is
  counted until the line is laid out, then corrected. S10 holds for a host that injects what fits;
  units 15 and 16 should drop an injection past its line before answering.
- **A lens that wraps counts once for the minimap.** `rowsAbove` avoids a layout, so under soft wrap
  a lens wider than the view puts the minimap's bar a row high. Harmless, and only with wrap on.
- **A squiggle over a mid-line break** starts its later rows at the row's left edge, under any
  injected text before the first column on that row. Selections do not: they use exact runs. Only
  mid-line multi-line ghost text can reach this.
- **`injectionsChanged()` with no range walks every line.** That is a lookup per line, not a layout,
  but units 15 and 16 should pass the range they changed.
- **Whatever answers `injections` must be up to date when `onDocumentChange` runs**, because the row
  map is spliced there. `TrackedRanges` moves with the same change, but the order must be checked.
- **Robolectric is not a device.** The comment on `rowShift` records that some Android devices
  space rows further apart than `lineHeight`; Robolectric shows a shift of 0, so that branch is
  exercised with a real shift only on skiko. It needs one look on a real phone before code lens
  ships on Android, as do Gboard and Samsung Keyboard on a line with a hint.

## Decision

**No step that was run failed, so nothing in the plan's "If steps fail" table applies yet.** S2's p95
and S9 are the only open steps, and only S9 can still change what ships.

| Feature | Rests on | Decision |
| --- | --- | --- |
| `before`/`after` text | S3, S4, S5, S8 | **Can ship**, once S2's p95 and S9 are in |
| Inlay hints | S3, S4, S5, S8, S9 | **Can ship**, once S9 is in. If S9 fails on hint count, add a per-view hint cap, as the plan says |
| Single-line ghost text | S3, S4, S5, S8 | **Can ship**, once S2's p95 and S9 are in |
| Multi-line ghost text | S6, S7 | **Can ship** on the same condition, with a device check on Android. No integer-row fallback is needed |
| Code lens | S6, S7, S10 | **Can ship** on the same condition, with a device check on Android. If S9 fails for a reason other than hint count, it is deferred, as the plan says |

The model stands as designed: per-line `OffsetMap`, `LineLayout` as the only reader of a layout, and
added rows as hard breaks inside the paragraph. `VisualLineMap` did not change. The unknown that
could have moved multi-line ghost text and code lens to 0.10, Compose's hard breaks with
`softWrap = false`, is answered: they work on all three platforms.

What is left before unit 15 starts: run S2's p95 and S9 alone on the machine after the merge. Neither
can change the model; they decide whether a hint cap is needed and whether code lens stays.
